# 按指定电脑环境构建和启动

本说明以《另一台电脑环境清单与执行计划.md》（2026-10-23）为基准。机器可读清单是 `scripts/target-environment.json`，目标模式使用这个清单进行检查，不会把本机其他 Node、pnpm 或 Python 版本当作指定版本。

## 1. 固定目标与安装目录

| 项目 | 目标 | 说明 |
| --- | --- | --- |
| 系统 | Windows 10/11 x64 | 使用普通用户运行项目 |
| Java | 完整 JDK 21 x64 | 同时核对 java、javac；21.0.10 最接近原清单，主版本必须是 21 |
| Node.js | 24.18.0 x64 | 严格匹配补丁版本 |
| pnpm | 11.25.0 | 严格匹配；前端按 pnpm-lock.yaml 安装 |
| Python | 3.11 x64 | 为算法创建本机虚拟环境；CPU 推理 |
| pip | 24.0 | 安装脚本固定版本，保证源码构建约束传递方式一致 |
| Maven | 3.9.x | 仅重新构建 Java 源码需要，运行现成 JAR 不需要 |
| 数据库 | 默认 H2 | 随后端启动，数据位于 backend/data，无需单独安装 |

推荐将工具放在以下项目相对位置。目标脚本优先选用这些工具，从而覆盖 `.env` 中旧电脑的工具路径；不会修改 `.env`、注册表或系统 PATH。

```text
face-attendance/
  .toolchain/
    jdk/bin/java.exe
    jdk/bin/javac.exe
    node/node.exe
    pnpm/node_modules/pnpm/dist/pnpm.mjs
    python311/python.exe
  algorithm/.venv-runtime/Scripts/python.exe
```

JDK、Node、pnpm 未放在这些位置时，可以使用本机 `JAVA_HOME`、`NODE_HOME`、`PNPM_EXE` 或 PATH，但仍必须通过上述精确版本检查。旧绝对路径不存在时会报错，请改成接收者真实路径，不能照抄发送者用户名或盘符。算法的目标模式固定使用 `.venv-runtime`，保留已有 `.venv`（例如 Python 3.12 轻量测试环境），不会混用。

工具应从各自官方发布渠道取得对应版本并核验下载校验和。不要把 Python embeddable ZIP 当作支持 venv/pip 的完整 Python 安装。安装 Python 3.11 x64 时保留 pip、venv 支持；没有项目内 Python 时，可在安装脚本显式传 `-PythonBase 'C:\你的Python311\python.exe'`。脚本不会自动下载或安装系统软件。

## 2. 新电脑首次准备

完整解压项目，在普通 PowerShell 切换到项目根目录。下面假定目录是 `C:\face-attendance`，请按实际位置修改。当前窗口的执行策略设置不改变机器的长期策略；单位管理策略可能禁止脚本，需要由管理员按本单位规则处理。

```powershell
Set-Location 'C:\face-attendance'
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

仅在没有 `.env` 的干净副本中生成新配置；已有文件时脚本会拒绝覆盖，避免更换已有模板的加密密钥。

```powershell
.\scripts\init-env.ps1
```

先检查业务工具，再按前端锁文件安装依赖。这一步不要求 Maven、Python、模型、MySQL 或 Nginx。

```powershell
.\scripts\check-target-env.ps1 -BusinessOnly -ToolsOnly
.\scripts\install-target-deps.ps1 -BusinessOnly
.\scripts\check-target-env.ps1 -BusinessOnly
```

最后一步还检查后端 `backend/target/face-attendance-1.0.0.jar` 是否存在以及已安装的前端版本是否与目标清单相同。若 JAR 缺失，先按第 5 节构建。pnpm 若拒绝依赖构建脚本，应先核对具体依赖与项目配置；不要删除锁文件或允许所有依赖脚本来绕过失败。

## 3. 两种启动入口

| 入口 | 实际行为 |
| --- | --- |
| 双击 `启动项目.cmd` | 目标业务模式：前端、后端、内置 H2；没有算法 |
| 双击 `启动完整刷脸.cmd` | 目标完整模式：再启动 Python 算法；先核对 Python、依赖、模型清单 |
| 双击 `停止项目.cmd` | 只停止本项目记录且身份匹配的进程，不停止独立 MySQL |

所有 CMD 在成功和失败后均等待按键，不会报错后直接闪退。成功启动后打开 `http://localhost:5173`。关闭 CMD 或浏览器不会停止后台服务；重复启动或切换模式前先用停止入口，并确认停止成功。

等价 PowerShell 命令：

```powershell
.\scripts\start.ps1 -Dev -BusinessOnly -TargetEnvironment
```

```powershell
.\scripts\stop.ps1
.\scripts\start.ps1 -Dev -TargetEnvironment
```

首次网页登录用本机 `.env` 的初始管理员凭据，改密后用新密码，初始配置不会自动更新。不要公开 `.env`。日志在 `.runtime`；启动中途失败可能已有本项目进程运行，阅读错误后先停止再重试。

原有 PowerShell 参数继续可用。未加 `-TargetEnvironment` 的旧启动命令仍使用原先的工具解析逻辑；本次目标环境交付请始终使用新增开关或中文 CMD。

需要独立 MySQL 时，先按[新电脑启动指南附录 C](新电脑启动指南.md)完成服务、建库和凭据配置，然后将 `-MySql` 加在上述带 `-Dev` 的 PowerShell 命令中。中文 CMD 默认 H2，不会暗中选用 MySQL。

## 4. 完整算法依赖和模型

仅在计划刷脸时执行。确保可用的完整 Python 3.11 x64 已准备好；下列脚本会创建本机 `.venv-runtime`，不会复制或删除旧虚拟环境。已有但不完整的目录会报错，请检查后再人工处理。

```powershell
.\scripts\install-target-deps.ps1
```

如果 Python 不在 `.toolchain/python311`：

```powershell
.\scripts\install-target-deps.ps1 -PythonBase 'C:\你的Python311\python.exe'
```

脚本优先使用 `algorithm/requirements-win-py311.lock.txt`；没有该完整锁时使用原来的固定直接依赖，明确提示传递依赖尚未锁定。可以用 `-AlgorithmLock` 显式指定经过验证的锁文件。安装后执行 `pip check`、直接版本核对与模块导入，拒绝 GPU 版 ONNX Runtime。

安装入口将 pip 固定为 `24.0`，并在这次安装期间通过 `PIP_CONSTRAINT` 传递 `algorithm/build-constraints-win-py311.txt`，将构建隔离环境中的 NumPy 也固定到 `1.26.4`。只固定运行时 NumPy，仍可能得到按 NumPy 2 编译的 InsightFace 扩展并出现导入错误。脚本用本地文件 URI 编码路径中的空格，成功和失败后都会恢复原来的 `PIP_CONSTRAINT`。不要直接用不带这项约束的 `pip install insightface` 替代安装入口。

若交付包包含本项目从官方 PyPI 源码编译并验证的 Windows x64 / CPython 3.11 wheel，目录必须是：

```text
algorithm/wheelhouse/
  insightface-0.7.3-cp311-cp311-win_amd64.whl
  manifest.json
```

安装脚本只接受这一份 InsightFace wheel，先核对文件名、Python/平台声明、来源记录和 wheel SHA-256，再从明确的本地路径安装。wheel 的哈希必须与交付清单一致；不匹配时应重新取得完整交付文件，不要自行重写哈希。清单是本项目的构建记录，不是 PyPI 官方签名；接收者仍需信任交付来源。其他 Python 依赖照常依据锁文件下载，因此这不是完整离线安装包。有这份可用 wheel 时，接收者无需为了编译 InsightFace 另装 C++ 编译工具；若运行时提示缺少 `VCRUNTIME` 等 DLL，应安装微软官方 x64 Visual C++ Redistributable。

`manifest.json` 使用 `schemaVersion: 1`、`pythonVersion: "3.11.9"`（实际构建补丁版本）、`platform: "win_amd64"`，`wheels` 数组只含一项，记录 `filename`、`sha256`、`sourceUrl` 和 `sourceSha256`。来源必须是 `https://files.pythonhosted.org/` 上的 `insightface-0.7.3.tar.gz`，两个 SHA-256 均为实际文件的 64 位十六进制摘要；只有源码经过核对、wheel 编译和导入验证完成后才能提供此清单。安装入口核验 wheel 内容哈希，源码哈希作为构建来源记录保留。

没有上述 wheel 时，安装入口会强制从 InsightFace `0.7.3` 源码构建，并禁用旧 wheel 缓存，避免复用按错误 NumPy 版本编译的包。这条路线需要 Microsoft C++ Build Tools 和 Windows SDK；首次安装编译工具可能需要管理员确认。不要改包版本或改用来源不明的 wheel 来绕过编译错误。源码路线可安装微软 [Visual Studio Build Tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/)，勾选 C++ 工具及 Windows SDK；仅运行已编译 wheel 时需要的运行库见微软 [Visual C++ Redistributable](https://learn.microsoft.com/cpp/windows/latest-supported-vc-redist)。

模型来源、许可和准备细节见[算法说明](../algorithm/Readme.md)。需要 buffalo_l 下 `det_10g.onnx`、`w600k_r50.onnx`、`1k3d68.onnx` 和 `models/face_landmarker.task`。确认来源后生成清单：

```powershell
& .\algorithm\.venv-runtime\Scripts\python.exe .\algorithm\scripts\model_manifest.py --model-dir .\algorithm\models
.\scripts\check-target-env.ps1
```

完整检查会核对模型文件 SHA-256、固定直接依赖、核心模块导入与 CPU provider；不会下载模型或启动服务。哈希清单用于检测后续变化，不是官方签名。不要为掩盖文件变化重新生成清单，应先核实来源。完整模型加载、照片提取、摄像头动作检测以及实际打卡仍须单独实测。

运行完整服务后，在系统运行页面确认模型和人员库状态，再完成人员录入、同步、浏览器授权与真实校准。默认相似度参数不是实测校准结果；不要将未完成的校准标为已经完成。不同组的录入、校准和测试图片应保持独立。

## 5. 从源码重新构建

已有匹配 JAR 只运行项目时跳过本节。源码构建需要 JDK 21、Maven 3.9.x、指定 Node/pnpm；在 `.env` 配置本机的 `MAVEN_EXE`，或通过 `-Maven` 传入可执行文件。可先检查：

```powershell
.\scripts\check-target-env.ps1 -BusinessOnly -Build -ToolsOnly
.\scripts\build.ps1 -TargetEnvironment
```

默认 Maven 配置为 `backend/maven-settings.xml` 的官方 HTTPS Central。网络无法访问时，可显式使用项目提供的 HTTPS 阿里镜像，仍需检查下载和测试结果：

```powershell
.\scripts\build.ps1 -TargetEnvironment -MavenSettings .\backend\maven-settings-aliyun.xml
```

构建始终同时传入 `-gs` 与 `-s` 指向选定配置，避免机器级旧 HTTP 镜像覆盖。构建默认运行 Java 与前端测试，再产出 JAR 和 `frontend/dist`。不要将 `-SkipTests` 的构建称为测试通过。算法测试需另行在目标 Python 环境执行：

```powershell
Push-Location .\algorithm
try {
    & .\.venv-runtime\Scripts\python.exe -m pip install -r requirements-test.txt
    if ($LASTEXITCODE -ne 0) { throw '测试依赖安装失败' }
    & .\.venv-runtime\Scripts\python.exe -m unittest discover -s tests -v
    if ($LASTEXITCODE -ne 0) { throw '算法测试未通过' }
} finally { Pop-Location }
```

## 6. 移交与验收记录

移交源码、固定依赖与锁文件、脚本、说明、对应构建 JAR 和前端 `dist`。本次目标环境压缩包排除模型与工具链；它们需按官方来源另行准备。若包含已验证的 InsightFace wheel，必须同时包含第 4 节规定的来源和哈希清单。JDK、Node 等本地工具可按其许可单独提供或让接收者安装；Python 虚拟环境必须在接收者电脑重新创建。

干净体验副本排除 `.env`、`.runtime`、`backend/data`、`frontend/node_modules`、所有 `.venv*`、构建缓存和实验参与者图片；这是排除发送副本中的文件，不是删除原电脑数据。已有员工、加密模板与考勤迁移应另行备份并安全移交密钥。

保存工具实际版本、测试报告、模型来源和 SHA-256。记录分别写明“工具版本一致”“依赖导入通过”“模型真实推理通过”“摄像头与打卡验收通过”“独立样本校准完成”，不能用前一项代替后一项。本文是执行说明，当前实际完成情况以[验证记录](validation.md)及本次交付报告为准。

# 管理员识别诊断与动态验证改进

## 本版完整包含

### 管理员识别诊断

新增管理员页面 `/diagnostics`、侧栏及系统运行入口。按帧展示业务人员库匹配分数、候选分差、首帧相似度、双眼闭合与张嘴系数、动作与阶段、处理耗时，以及自然基准和完成动作数；最近80帧只保留在页面内存，失败帧可查看。

未测量的字段显示空值；单候选库不显示虚假的分差。诊断不包含姓名、候选员工编号、原图或512维特征。

### 前后端授权协调

诊断会话及WebSocket使用 `/api/v1/kiosk/diagnostics` 前缀，兼容既有 `/api/v1/kiosk` 设备Cookie，无需因新增入口重复授权。独立的管理员安全规则优先于公共打卡规则；每帧及数值转发前再次检查管理员登录、账号有效性和测试模式。

Java只允许白名单数值进入管理员诊断连接。公共连接不转发诊断字段，查询参数不能开启诊断。登录失效后不能继续接收数值。

### 动作基准与流程

自然睁眼上限由0.20调整为0.30，统一用于基准、眨眼恢复和结束收尾。闭眼下限0.55、闭嘴上限0.15、张嘴下限0.35保持。初始两帧自然状态完成后不再重复检查同一初态；第二项动作及最后三帧自然状态检查保留。

提示强调闭眼约2秒后恢复、适度张嘴并保持到闭嘴提示，避免夸张表情造成身份分数下降。每帧身份和首帧一致性检查保持，没有擅自降低管理员设置的身份门槛。

### CPU 推理与时间预算

新增应用内CPU适配器，显式创建检测、3D姿态和识别三个必需模型的ONNX会话，不修改第三方安装文件或模型权重。默认8个 intra-op线程、1个 inter-op线程，可用 `CPU_INFERENCE_THREADS` 设置1～8。

浏览器、Java转发层和算法采集预算统一为50秒，浏览器另留2秒接收结果；整个会话仍最多60秒，单帧200KiB、80帧和累计12MiB边界不变。沿用连接就绪与逐帧确认机制。

## 验证与边界

- 后端35项、算法56项、前端6项协议测试及TypeScript检查通过。
- 诊断界面以模拟摄像头验证了失败帧显示、公共页隔离和员工拒绝访问；Cookie路径通过浏览器请求及后端测试验证。
- 8线程公开样本小基准为约239ms，默认约284ms，特征余弦相似度在输出精度内为1.0；这不是实时摄像头或所有硬件的性能承诺。
- 使用者已确认本机试用效果可用，并授权本版合并。单次试用不等于识别准确率、陌生人拒绝率或防伪能力的完整验收。
- 0.30是结合本机诊断提出的动作工作点，其他人员、设备与环境仍需独立验证。

## 升级说明

本版不新增数据库迁移，继续保留上一版V2测试模式及测试事件隔离。重新安装或升级时不覆盖 `.env`、数据库或加密密钥；备份后构建并重启后端，更新算法及前端。

保留仓库内已参数化的手机启动和防火墙脚本。模型、证书私钥、照片、数据库、虚拟环境、日志、工具链及二进制产物均不随源码上传。

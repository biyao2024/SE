## 3. 项目如何交给对方

建议给对方一份干净副本，至少包含：

```text
face-attendance/
  Readme.md
  .env.example
  scripts/
  backend/                 # 包含源码、配置和 target 下的运行 JAR
    target/face-attendance-1.0.0.jar
  frontend/                # 包含源码、package.json、pnpm-lock.yaml、.npmrc
  algorithm/               # 包含源码、requirements 文件和 scripts
  docs/
  deploy/
  启动项目.cmd
  停止项目.cmd
```

制作“全新体验”副本时，不要带以下内容：

- 根目录 `.env`：包含本机密钥、密码和工具路径，对方应自己生成。
- `frontend\node_modules`：让对方按锁文件重新安装。
- `algorithm\.venv`：让对方在本机重新创建。
- `.runtime`：是日志和进程记录，不应迁移。
- `backend\data`：包含旧账号、人员信息和业务数据，新体验不需要。
- `.m2`、`.pnpm-store`、临时文件和缓存。

这里指的是从发送副本中排除，不是删除原电脑数据。需要迁移已有员工、人脸和考勤数据时，要另外制定备份与密钥迁移方案，不能按“全新体验”操作。

## 4. 第一阶段：先复现业务前后端

### 步骤 1：安装或复用工具

先在对方电脑检查现有工具，再决定是否安装。为对齐当前电脑，目标为 JDK 21、Node 24.18.0、pnpm 11.25.0。

安装 Java 时配置 `JAVA_HOME` 和 PATH；Node 安装时保留 npm 和 PATH。完成后重新打开 PowerShell：

```powershell
java -version
javac -version
$env:JAVA_HOME
node --version
npm.cmd --version
```

Java 应为 21，Node 对齐版本应为 v24.18.0。若已有兼容版本可先复用，但要记录版本差异。

尚未安装 pnpm 时执行：

```powershell
npm.cmd install --global pnpm@11.25.0
pnpm.cmd --version
```

### 步骤 2：解压并确认目录

将项目完整解压到 `C:\face-attendance`，在 PowerShell 执行：

```powershell
Set-Location 'C:\face-attendance'
Test-Path .\scripts\start.ps1
Test-Path .\backend\target\face-attendance-1.0.0.jar
```

两项都应为 True。若找不到脚本，先检查是否外面多套了一层文件夹；若 JAR 缺失，向提供者索取，或按第 7 节构建。

### 步骤 3：生成自己的配置

只对干净副本执行一次：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\scripts\init-env.ps1
notepad.exe .env
```

检查 `JAVA_HOME`、`NODE_HOME`、`PNPM_EXE`，不能保留发送者电脑路径。

- `JAVA_HOME`：本机 JDK 21 根目录，不含 `bin`，也不是 `java.exe` 路径。
- `NODE_HOME`：本机 `node.exe` 所在目录；若 Node 已在 PATH 且没有配置该项，可以不新增。
- `PNPM_EXE`：可设为 `pnpm.cmd`；主要供构建脚本使用。
- `PYTHON_EXE`：保留 `algorithm/.venv/Scripts/python.exe`，第二阶段创建它。
- `MODEL_DIR`：保留 `algorithm/models`。

初次登录使用本机生成的 `BOOTSTRAP_ADMIN_USERNAME` 和 `BOOTSTRAP_ADMIN_PASSWORD`。不要在文档、截图或群聊中公开整份 `.env`，也不要把旧电脑的密码和密钥覆盖进去。

### 步骤 4：安装前端依赖

```powershell
Push-Location .\frontend
pnpm.cmd install --frozen-lockfile
```

只有安装成功后才继续。pnpm 11 可能提示 `ERR_PNPM_IGNORED_BUILDS`，本次原电脑安装出现过 `esbuild` 脚本未获批准的提示。若遇到该提示，保持在 frontend 目录，执行：

```powershell
pnpm.cmd approve-builds
```

在交互列表中核对并选择 `esbuild`，完成确认，再执行：

```powershell
pnpm.cmd rebuild esbuild
pnpm.cmd install --frozen-lockfile
```

不要直接批准来源不清楚的全部构建脚本。若交互或命令行为不同，保留实际提示排查。

安装完成后返回项目根目录并检查：

```powershell
Pop-Location
Test-Path .\frontend\node_modules\vite\bin\vite.js
```

应为 True。保留原有 `pnpm-lock.yaml`，不要通过删锁文件来解决版本问题。

### 步骤 5：启动并验收

```powershell
.\scripts\start.ps1 -Dev -BusinessOnly
```

看到前后端启动成功后，浏览器打开 <http://localhost:5173>。检查：

```powershell
(Invoke-WebRequest -Uri 'http://localhost:5173/api/v1/health' -UseBasicParsing -TimeoutSec 15).StatusCode
```

应返回 200。使用本机初始密码登录并完成改密，再创建一个测试员工。首次改密后使用新密码，`.env` 的初始密码不会跟着更新。

这一阶段不启动算法，不能刷脸；出现 Business-only mode 提示符合预期。

## 5. 第二阶段：准备完整算法环境

### 步骤 6：创建本机 Python 环境

安装或复用 Python 3.11 64 位。不要复用从另一台电脑复制的虚拟环境。以下操作假设发送副本中没有 `.venv`，并且 `py -3.11` 可以找到本机 Python：

```powershell
Set-Location 'C:\face-attendance\algorithm'
py -3.11 --version
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip setuptools wheel
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip check
```

如果没有 `py` 命令，可用本机 Python 3.11 的完整可执行文件路径替代 `py -3.11`。InsightFace 在 Windows 上可能需要 Visual Studio Build Tools 的 C++ 桌面开发组件和 Windows SDK；仅在出现编译器相关错误时按错误补齐。

检查核心依赖导入：

```powershell
.\.venv\Scripts\python.exe -c "import insightface, onnxruntime, mediapipe, cv2, numpy, fastapi; print('imports OK')"
```

这一行成功不代表模型已能推理，还要完成后续模型加载和真人测试。

### 步骤 7：准备模型文件

模型不需要自行训练，下载官方预训练文件即可。必须与当前适配器要求一致，不要随意换一个人脸模型。

- InsightFace 官方发布页：<https://github.com/deepinsight/insightface/releases/tag/v0.7>，获取 `buffalo_l.zip`。
- MediaPipe Face Landmarker 官方模型说明：<https://ai.google.dev/edge/mediapipe/solutions/vision/face_landmarker>，获取 Face Landmarker task bundle，命名为 `face_landmarker.task`。

InsightFace 官方预训练模型限非商业研究使用；商业部署另行处理许可。模型来源、日期和许可说明应保留。

解压后的最低文件布局：

```text
algorithm/models/
  face_landmarker.task
  insightface/models/buffalo_l/
    det_10g.onnx
    w600k_r50.onnx
    1k3d68.onnx
```

buffalo_l 包中其他文件可以保留。不要多套一层 `buffalo_l\buffalo_l`。在 algorithm 目录生成本地校验清单：

```powershell
.\.venv\Scripts\python.exe scripts\model_manifest.py --model-dir models
```

生成 `models\manifest.json`。该清单检测文件变化，不代表官方签名；应先确认下载来源。

### 步骤 8：切换到完整服务

回到根目录，确认 `.env` 中 `PYTHON_EXE=algorithm/.venv/Scripts/python.exe` 和 `MODEL_DIR=algorithm/models` 正确，然后执行：

```powershell
Set-Location 'C:\face-attendance'
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\scripts\stop.ps1
```

停止成功后启动：

```powershell
.\scripts\start.ps1 -Dev
```

此时不能加 `-BusinessOnly`。管理员进入“系统运行”，确认算法服务和识别模型正常。仅看到端口启动，不代表模型已经就绪；缺模型时进程可能存在但 ready 为 false。

当前项目的 `启动项目.cmd` 固定启动业务模式。算法阶段请使用上面的完整启动命令，避免双击后误回业务模式。

## 6. 第三阶段：录入、试跑、校准和验收

按以下顺序执行：

1. 管理员创建部门和参与测试的员工档案；初始 admin 不等于已经有员工档案。
2. 每位要打卡的参与者知情同意后，录入 3 张清晰单人照片。照片用于提取特征、建立人员库，不会用于从头训练模型。
3. 在“系统运行”点击“重新同步人员库”，确认已同步。
4. 在“打卡设备”授权当前浏览器。设备凭据绑定该浏览器，换浏览器或清 Cookie 后需重新授权。
5. 初步试跑可保留默认相似度 0.50、分差 0.08；默认值是工程初值，不能标成实测校准结果。若为演示勾选确认放行，应在实验记录中明确写“默认参数试跑，未完成校准”。
6. 公共打卡选择当前有效的签到或签退类型，允许摄像头访问，按提示完成动作，确认考勤查询出现正确员工的记录。
7. 再重新采集校准和测试样本，统计分数、选阈值并保留报告；管理员填入结果、勾选已校准并保存。
8. 固定参数后测试已录入人员、未录入人员、重复打卡、非打卡时间、动作检测和设备授权失效。

### 样本起步方案

| 样本组 | 起步建议 | 用途 |
|---|---|---|
| 录入 | 每人 3 张 | 建立人员库 |
| 校准 | 每人另外采集 10～20 张，覆盖不同光线和距离 | 选择阈值 |
| 测试 | 参数固定后，每人再采集 10～20 张 | 验证效果 |
| 未录入人员 | 经本人同意，留 1～2 人暂不录入，分别提供校准、测试样本 | 检查陌生人是否被误接受 |

这是小组演示的起步规模，不足以证明真实大规模场景中的准确率。三组图像不能复用；校准和测试都需要已录入及未知人员。可以使用相同参与者重新采集，不要求找三批不同的人。

### 校准执行方式

项目已有 `algorithm\scripts\calibrate.py`，输入分数 CSV，输出参数和评估报告。**当前没有一键采集和自动生成分数 CSV 的页面**；需要先按固定人员库提取各样本的原始检索分数并整理 CSV，不能用手填的虚构分数代替。

CSV 表头：

```csv
sample_id,split,truth_id,candidate_id,score,runner_up_score,model_version
```

`split` 为 calibration 或 test，未知人员 `truth_id=UNKNOWN`；同一批实验使用同一个模型版本。详细字段要求见 `algorithm\Readme.md`。

准备好 `algorithm\experiments\scores.csv` 后，在 algorithm 目录运行：

```powershell
.\.venv\Scripts\python.exe scripts\calibrate.py --samples experiments\scores.csv --output experiments\calibration-result.json --max-unknown-acceptance 0.01 --max-wrong-identity 0.01
```

命令中的 0.01 是筛选目标，不能写成“系统实测错误率为 1%”。样本不满足目标时，应如实报告，不能保证脚本一定能找到合格参数。

完整模型、摄像头和业务流程通过后，在 algorithm 目录记录最终依赖：

```powershell
.\.venv\Scripts\python.exe -m pip freeze > requirements-win-py311.lock.txt
```

同时记录 Python 版本、操作系统、CPU、模型文件清单和实验结果。这时才有可交给下一位组员复现的“完整刷脸已验证环境”。

## 7. 仅在需要重新构建后端时使用 Maven

已有 JAR 且只运行项目时跳过本节。更改 Java 源码后，需使用 JDK 21 和 Maven 3.9 系列重新构建；原电脑 `.env` 的 Maven 路径不可照搬。

在新电脑安装或解压 Maven，并把 `.env` 的 `MAVEN_EXE` 设置为实际 `mvn.cmd` 路径，`PNPM_EXE=pnpm.cmd`。停止服务后，在根目录执行：

```powershell
.\scripts\build.ps1
```

正常会执行后端测试与打包、前端测试与构建。Maven 下载问题可参考项目提供的镜像配置，但不要跳过失败测试来冒充构建验收。

| 项目 | 位置或端口 |
|---|---|
| 网页 | `http://localhost:5173` |
| Java 后端 | `127.0.0.1:8080` |
| Python 算法服务 | 完整模式使用 `127.0.0.1:8000` |
| H2 数据文件 | `backend\data\attendance.mv.db` |
| 日志和进程记录 | `.runtime` |

业务模式启动：

```powershell
.\scripts\start.ps1 -Dev -BusinessOnly
```

完整刷脸启动：

```powershell
.\scripts\start.ps1 -Dev
```

停止：

```powershell
.\scripts\stop.ps1
```

重新启动前先正常停止，确认停止成功再启动。关闭浏览器不等于停止服务。

| 提示 | 处理方向 |
|---|---|
| 工具路径指向别人电脑 | 检查 `.env` 的 JAVA_HOME、NODE_HOME、PNPM_EXE、PYTHON_EXE |
| Python 提示旧目录不存在 | 不复用旧 `.venv`，在新电脑创建环境 |
| 模型不可用 | 检查文件层级、校验清单、依赖和算法日志 |
| 请管理员完成阈值校准 | 系统运行中的校准确认尚未完成；时间限制与模型状态仍需另外满足 |
| 非打卡时段 | 检查当前规则及选择的签到/签退；默认签到 06:00～11:59:59，签退 12:00～23:59:59 |
| 修改时间提示重叠 | 签到结束必须早于签退开始，上下班时间必须分别在各自窗口内 |
| 保存时间后当天仍无效 | 规则修改次日生效，需提前安排实验时段 |
| 端口占用或进程记录存在 | 先确认是否已经运行；需要重启则用 stop.ps1，不随意结束其他进程 |
| pnpm 下载失败 | 检查联网、代理、证书及完整错误，不关闭证书校验 |
| spawn EPERM | 原电脑在自动化沙箱内启动前端时出现过；普通本机终端先直接启动，若仍发生再检查权限和安全软件 |

本路线只允许本机访问。对方在自己的电脑打开自己的 localhost；手机或另一台电脑无法通过这个地址访问发送者的系统。

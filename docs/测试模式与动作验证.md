# 测试模式与动作验证

## 全天测试打卡

管理员进入“系统运行 → 识别与动作检测”，开启“全天测试打卡”并点击“保存识别设置”。保存立即生效，会取消旧的未完成会话。公共打卡页刷新状态后显示测试提示。

测试模式只跳过签到/签退时间窗口与整天请假冲突。设备授权、已录入在职人员、模型、同步版本、校准确认、识别阈值和已开启的动作检测仍需通过。默认关闭；测试完成请关闭并保存。

成功事件以 `FACE_TEST` 保存，提示“【测试】签到/签退成功”。在“考勤记录”底部点击“按上方日期加载测试记录”查看。重启后记录保留；不参与正式日考勤、仪表盘、导出报表、请假冲突和正式打卡去重。测试记录内部仍执行同人同方向30秒去重。员工只能读取自己的测试记录，管理员可读取全部。

数据库 V2 迁移仅新增设置与会话的 test_mode 字段，已有会话及配置默认非测试；事件使用既有 source 字段标记。切换模式会改变配置版本，创建时将模式固定在会话上，避免一半正式、一半测试。

## 身份不稳定

同一会话内会逐帧检查：候选是否始终为同一个员工、匹配分数及候选分差是否达标、当前特征与首帧是否一致。张嘴、闭眼、转头、距离改变、逆光、模糊或录入模板质量差都可能使分数变化；“有时成功”不证明每一帧都稳定。只有一个有效人员时不使用第二候选分差，仍检查分数和首帧一致性。

此修改没有降低身份阈值或允许切换人员。新增更具体的失败提示，便于区分未达匹配门槛与候选/首帧变化。保持单人、正面光线，先自然睁眼闭嘴，按提示缓慢闭眼再睁开、张嘴再闭嘴，最后恢复自然状态。

## 超时修复

原前端每167毫秒发送一帧，CPU串行处理慢时会排队，动作提示滞后，12秒经常不足。现在只有上一帧处理并确认后才能发送下一帧，首次欢迎提示不能充当确认，避免历史画面积压。

浏览器、Java转发层、Python算法三处采集预算统一50秒，前端另留2秒收尾；会话总有效期仍最多60秒，单帧200KiB、最多80帧、累计12MiB限制保持。Java确认算法连接建立后才允许发送首帧，并透传逐帧确认。提示分为睁眼/闭眼/再睁眼，或闭嘴/张嘴/再闭嘴，避免在基准阶段提前做动作。仍可能因相机权限、动作阈值、采集质量、CPU负载或身份失败而不通过，需要真人测试，不能承诺所有超时都已消除。

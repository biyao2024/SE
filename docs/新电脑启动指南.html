在新电脑上启动人脸考勤项目

适用：Windows 10/11 的 64 位电脑，第一次接触前后端项目的用户。更新日期：2026-10-24。

本次依赖按目标电脑环境清单固定；完整安装和模型步骤见目标环境构建说明。请使用本次 face-attendance-target.zip，不要混用此前的 face-attendance-preview.zip 与新启动命令。

模型环境完成后，继续阅读真人刷脸操作步骤；本次实际验证范围见环境对齐与模型验证。

照着第 1—8 步操作，可以在新电脑打开登录页，体验人员管理、审批、考勤查询和报表。推荐使用随文档提供的 face-attendance-target.zip：里面已放入编译好的后端程序，默认体验路线不用安装 Maven、Python、MySQL 或 Nginx。要使用项目计划中的独立 MySQL 数据库，请按下方的数据库路线选择操作。

这条路线运行真实的前后端业务服务，使用本地 H2 数据库保存数据；没有加载人脸模型，因此暂时不能录入人脸或完成刷脸打卡。 完整刷脸环境的入口在附录 B。

本指南有两个版本：新电脑启动指南.html 可以双击后用浏览器阅读；.md 是便于维护的文本版。两份内容相同。阅读 HTML 文档不需要先启动项目。

先选择数据库

项目有数据库。默认体验使用的 H2 内嵌在 Java 后端中：启动后端时自动启动数据库，停止后端时自动关闭；数据保存在 backend\data\attendance.mv.db，重启后仍然存在。 所以 H2 路线没有单独的“安装和启动数据库”命令。

原计划的正式数据库是 MySQL 8.4，它是单独安装、单独运行的 Windows 服务，必须先启动 MySQL，再启动后端和前端。两种路线如下：

你想做什么操作顺序启动命令
先快速看页面，用 H2 保存数据完成第 1—8 步scripts\start.ps1 -Dev -BusinessOnly -TargetEnvironment
安装独立 MySQL，实际连接数据库完成第 1—6 步 → 附录 C → 第 8 步登录scripts\start.ps1 -Dev -BusinessOnly -MySql -TargetEnvironment

只修改 .env 中的 DB_URL 不会把默认开发模式切到 MySQL，必须加 -MySql。 这个选项已包含在更新后的转移包中。MySQL 和 H2 各自保存一套数据，切换不会自动迁移账号、密码或考勤记录。

1 准备项目文件

推荐使用转移压缩包

  1. 在原电脑取得 delivery/face-attendance-target.zip，通过 U 盘或文件传输复制到新电脑。
  2. 右键压缩包，选择“全部提取”。不要直接在压缩包窗口中运行文件。
  3. 将解压得到的整个 face-attendance 文件夹放到一个自己有写入权限的位置，例如 C:\face-attendance。不用与原电脑的盘符一致，也不需要安装 Codex 或 IntelliJ IDEA。
  4. 打开这个文件夹，确认里面直接有 Readme.md、backend、frontend、scripts 和 .env.example。如果外面又套了一层同名文件夹，继续进入内层。
  5. 确认能找到 backend\target\face-attendance-1.0.0.jar。这是已编译的后端程序。找不到时，先看附录 A，不要直接执行启动步骤。

转移包包含源码、启动脚本、说明文档和后端 JAR；不包含原电脑的账号密码、旧数据库、日志、前端依赖或 Python 虚拟环境。首次安装前端依赖仍然需要联网。

如果拿到的是直接复制的旧项目

建议向提供者索取上述干净转移包。直接复制的 .env 可能含原电脑的工具路径和密码；backend\data 会保留原账号和旧密码；.runtime 会留下原进程记录，容易导致新电脑无法启动。

体验一个全新的系统，与迁移原有业务数据是两件事。 有需要保留的旧数据时，先按 部署与备份说明 制定迁移方案。不要为了解决登录问题删除数据库，也不要给已有加密模板随意更换密钥。

2 安装 Java 21

Java 用来运行后端，也就是保存数据、检查账号和处理业务的程序。

  1. 打开 Eclipse Temurin 下载页。选择 版本 21、Windows、x64、JDK，下载安装包 .msi。
  2. 双击安装包，按提示继续。到“Custom Setup／自定义安装”时，启用 Add to PATH 和 Set JAVA_HOME／更新 JAVA_HOME 两项。
  3. 完成安装。若电脑原来已经有 Java 8 或 Java 17，仍需确保本项目实际使用 Java 21。

上述选项来自 Temurin 官方 Windows 安装说明。补丁版本可以更新，主版本按本项目已验证的 21 使用。

3 安装 Node.js 和 pnpm

Node.js 负责运行前端开发服务；pnpm 负责把前端需要的依赖下载到项目中。

  1. 打开 Node.js 官方下载页。选择文档指定的 24.18.0，操作系统选 Windows，架构选 x64，下载该版本的 Windows Installer .msi。也可使用官方版本归档；不要选择其他补丁版本。
  2. 安装时保留 npm 和 Add to PATH。若出现额外安装原生模块编译工具的选项，本指南的业务体验路线不需要勾选。
  3. 安装完后，关闭之前打开的终端窗口。点击开始菜单，搜索并打开 Windows PowerShell，使用普通窗口即可。
  4. 依次复制下面的命令，每次粘贴一行后按回车。只复制代码框中的命令，不要复制 PS C:\...> 这样的终端提示符。
PowerShell 命令
java -version

应看到 21 开头的 Java 版本。

PowerShell 命令
javac -version

应看到 javac 21...。

PowerShell 命令
$env:JAVA_HOME

应显示实际 JDK 21 的文件夹路径，例如 C:\Program Files\Eclipse Adoptium\jdk-21...，末尾不应是 bin。如果为空或指向旧版本，先按第 9 节修正，再继续。

PowerShell 命令
node --version

必须看到 v24.18.0。

PowerShell 命令
npm.cmd --version

能显示版本号后，安装 pnpm 11.25.0：

PowerShell 命令
npm.cmd install --global pnpm@11.25.0

等待下载结束，再检查：

PowerShell 命令
pnpm.cmd --version

必须看到 11.25.0。本文使用 .cmd 后缀，避免 PowerShell 对同名 .ps1 文件的执行策略影响。安装方式参照 pnpm 官方说明。

如果出现红色错误，先处理错误，再执行下一步。 下载慢时等待当前命令结束，不要同时打开多个安装窗口。

4 在项目根目录打开 PowerShell

  1. 用资源管理器打开解压后的 face-attendance 文件夹，也就是直接看得到 Readme.md 和 scripts 的那一层。
  2. 点击资源管理器上方的地址栏，输入 powershell，按回车。这会在当前文件夹打开 PowerShell。
  3. 输入下面两行，确认操作位置正确：
PowerShell 命令
Get-Location
PowerShell 命令
Test-Path .\scripts\start.ps1

第二条应输出 True。如果是 False，说明打开的文件夹层级不对。

  1. 为本次打开的窗口允许执行已确认来源的项目脚本：
PowerShell 命令
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass

若出现确认提示，输入 Y 后回车。这个设置只作用于当前 PowerShell 进程，关闭窗口后失效，不修改电脑的永久策略。若单位电脑有强制策略阻止执行，交给电脑管理员处理。PowerShell 官方说明

接下来的初始化、安装、启动和停止步骤，都在这个项目根目录中执行。

5 生成新电脑自己的配置和初始密码

只在这个干净项目第一次使用时执行：

PowerShell 命令
.\scripts\init-env.ps1

成功时会出现 Created .env ...。项目根目录会新建一个 .env 文件，里面有独立生成的初始密码和服务密钥。

然后用记事本打开：

PowerShell 命令
notepad.exe .env

找到这两项：

配置示例或预期结果
BOOTSTRAP_ADMIN_USERNAME=admin
BOOTSTRAP_ADMIN_PASSWORD=这里会是本机生成的随机密码

上面只是说明格式，不要把“这里会是本机生成的随机密码”填回文件。用户名通常是 admin；登录密码是你自己文件中 BOOTSTRAP_ADMIN_PASSWORD= 后面的全部内容。

复制密码时，只复制第一个等号后面的值。不要复制字段名、换行或额外空格；密码中如果还有 +、/、= 等符号，也要完整保留。可以先保存到个人密码管理器，不要把整份 .env 发到群里。

默认 H2 路线此时不需要修改 DB_PASSWORD=CHANGE_ME、NGINX_EXE、PYTHON_EXE 或其他模型配置。选择 MySQL 路线时，完成前端依赖安装后按附录 C 填写真实的数据库连接和密码；需要真实刷脸或 Nginx 时再看附录 B。

如果提示 .env already exists，表示已经初始化过，脚本正在保护已有密钥。直接查看现有 .env 并继续；若它来自旧电脑，则回到第 1 节，使用新的干净解压目录。

7 启动前后端并打开网页

在项目根目录运行：

PowerShell 命令
.\scripts\start.ps1 -Dev -BusinessOnly -TargetEnvironment

参数含义：-Dev 使用本地开发配置，默认随 Java 启动 H2 数据库；-BusinessOnly 先启动业务前后端，不启动人脸算法。首次启动需要一些时间，等待程序返回，不要连续重复点击或运行。选择 MySQL 的用户，用附录 C 的命令代替本节启动命令。

成功时会看到类似文字，PID 数字每次可能不同：

配置示例或预期结果
backend started (PID ...).
frontend started (PID ...).
Development URL: http://localhost:5173 (local computer only).

随后出现算法未启动的 Business-only mode 提示属于预期结果，不代表前后端启动失败。

继续执行：

PowerShell 命令
Start-Process 'http://localhost:5173'

或者自行打开 Edge/Chrome，在地址栏输入 http://localhost:5173。应看到人脸考勤系统的登录页。

如果要检查连接，执行下面一行，应输出 200：

PowerShell 命令
(Invoke-WebRequest -Uri 'http://localhost:5173/api/v1/health' -UseBasicParsing -TimeoutSec 15).StatusCode

请始终使用上面的 localhost:5173 地址。不要双击项目的 index.html 来运行系统，也不要把 8080 当成网页入口。这里仅允许本机访问，另一台电脑或手机不能通过自己的 localhost 访问它。

8 登录和第一次体验

  1. 输入用户名 admin 和第 5 步获取的完整初始密码。
  2. 首次登录会要求修改密码。新密码至少 12 个字符，包含字母和数字，UTF-8 编码最多 72 字节，且不能与旧密码相同。使用纯英文字母、数字和常见英文符号时，长度为 12—72 个字符；请注意大小写并安全保存。
  3. 修改完成后保存新密码。以后使用新密码登录，.env 中的初始密码不会自动跟着改变。
  4. 进入管理页面，先查看仪表盘，再到人员管理新建一个虚构测试员工，体验规则、审批、考勤查询和报表。

全新数据库没有员工考勤记录，仪表盘为空或数量为零是正常的。初始 admin 是独立管理账号，没有关联员工档案；要体验员工申请流程，需要先创建员工，并使用那个员工的账号登录。

不要把“账号或密码错误，或账号已停用”当成程序没有启动。这条消息表示服务器已经处理登录请求，只是没有接受这组凭据。具体排查顺序见下一节。

9 常见问题和处理顺序

提示账号或密码错误或账号已停用

  1. 确认打开的是这台电脑的 http://localhost:5173，用户名为当前项目配置的 admin。
  2. 如果从未改过密码，重新打开当前项目根目录的 .env，复制 BOOTSTRAP_ADMIN_PASSWORD= 后的完整内容。特别检查大小写、末尾符号和是否带入换行。
  3. 如果已经完成首次改密，就使用自己设置的新密码；不要继续使用 .env 里的初始密码。
  4. 如果复制过旧电脑的 backend\data，里面保留的是旧账号和旧密码。程序仅在账号表为空时创建初始管理员，修改 .env 后重启不会重置已有密码。
  5. 员工账号还需要确认员工未被停用。若连续尝试过多出现限流提示，等待 5 分钟后再试。
  6. 若忘记新密码且没有其他可用管理员，联系项目维护者进行保留数据的密码恢复。当前没有“忘记密码”入口；不要删除数据库来尝试修复。

页面上的“请求编号”用于定位日志，不是账号或密码。向维护者提供报错截图、发生时间、请求编号即可，不要提供 .env 全文。

端口被占用或已有进程记录

如果提示 Port 8080/5173 is occupied 或 A process record already exists，先检查之前是否已经启动本项目。已经启动且网页可用时，不需要再启动一次。

需要重新启动本项目时，在同一项目根目录先执行：

PowerShell 命令
.\scripts\stop.ps1

确认停止成功，再执行第 7 步。脚本只会停止它能够核对归属的本项目进程；如果其他软件占用了端口，它不会替你关闭那个软件。此时先通过任务管理器或维护者查清占用来源，避免结束陌生进程。

网页打不开或显示网络错误

  1. 检查启动命令是否真正完成。若中途报错，前端可能尚未启动。
  2. 确认地址是 http://localhost:5173，没有写成 https，也没有遗漏端口。
  3. 查看下面的日志。即使日志显示出错，也先保留文件供维护者排查。
PowerShell 命令
Get-Content .\.runtime\backend.stdout.log -Tail 60
PowerShell 命令
Get-Content .\.runtime\backend.stderr.log -Tail 60
PowerShell 命令
Get-Content .\.runtime\frontend.stderr.log -Tail 60
  1. 若启动只成功了一半，执行 stop.ps1 清理已启动的本项目服务，处理日志中的原因后再启动。

登录界面报 403 或安全令牌相关错误时，先刷新页面再试；仍有问题时关闭该网站标签页，重新打开相同的 localhost:5173 地址。HTTP 演示应保留 -Dev 参数，避免误用正式部署的安全 Cookie 设置。

依赖下载失败

前端安装出现网络超时或连接失败时，先确认浏览器可以联网，再重新执行第 6 步。证书或代理错误应交给网络管理员排查，不要通过关闭证书校验来继续。若提示锁文件与源码不一致，取得同一版本的完整项目，不要先删除 pnpm-lock.yaml。

业务体验路线不必运行 check-env.ps1 -Dev：这个检查还要求 Maven、Python 和模型，它们未安装时会显示失败，但不影响这里的前后端体验。源码构建遇到 Maven 下载问题时见附录 A。

数据看起来丢失或换了账号

通过本项目的 start.ps1 启动时，Java 的工作目录固定为 backend，因此使用的是 backend\data 中的数据。手动从其他目录执行 java -jar 可能生成另一份数据库。请统一使用本指南脚本，不要混用启动方式。

10 停止服务和下次再打开

关闭浏览器只会关闭页面，关闭 PowerShell 窗口也不等于停止后台服务。

需要停止时，在项目根目录打开 PowerShell，执行：

PowerShell 命令
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
PowerShell 命令
.\scripts\stop.ps1

下次使用时，先在项目根目录打开 PowerShell，再依次执行。先调用停止脚本，是为了清理上次关机或异常退出留下的进程记录；如果项目仍在运行，它也会先停止本项目服务：

PowerShell 命令
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
PowerShell 命令
.\scripts\stop.ps1

附录 C 安装和启动独立 MySQL 数据库

本附录把数据库单独运行起来，再让前后端连接它。前提是已完成第 1—6 步，拥有 Java、Node、前端依赖、后端 JAR 和本机 .env。这条路线暂不启动人脸算法，也不要求先配置 Nginx。

C1 下载并安装 MySQL Server

  1. 打开 MySQL Community Server 8.4 官方下载页，选择 Windows 的 64 位 MSI Installer。下载的是 MySQL Server，不是只提供可视化管理界面的 Workbench。
  2. 运行 .msi 完成安装，并继续打开随安装包提供的 MySQL Configurator 完成数据库配置。若安装器提示缺少运行库，先按安装器指引安装对应组件，再继续。
  3. 记下安装目录。下文示例使用 C:\Program Files\MySQL\MySQL Server 8.4；如果安装到了其他位置，命令中的路径也要跟着改。

MySQL 8.4 的安装包与配置工具说明见 官方 Windows 安装文档。如果电脑已有承载其他项目的 MySQL，不要覆盖升级或卸载它；先让维护者确认能否复用。

C2 在配置向导中设置服务

按以下选项完成 MySQL Configurator；不同补丁版本的文字可能略有不同：

配置页面建议填写
Type and NetworkingDevelopment／开发电脑；保持 TCP/IP 启用；端口 3306
Open Windows Firewall port for network access取消勾选。本项目由同一台电脑的 Java 访问数据库，不需要让局域网直接连接 3306
Accounts and Roles设置并保存自己的 MySQL root 管理员密码；稍后另建项目专用账号
Windows Service勾选作为 Windows 服务运行，服务名称填写 MySQL84；勾选开机自动启动
Apply Configuration点击 Execute／执行，等待全部配置步骤成功，再 Finish／完成

这里的 root 密码管理数据库，与网页上的 admin 密码不同。配置选项说明

C3 启动数据库并检查状态

图形方式：按 Win + R，输入 services.msc，按回车。在服务列表找到 MySQL84，状态应为“正在运行”；如果尚未运行，右键选择“启动”。以后它通常会随 Windows 自动启动。

也可以在开始菜单搜索 PowerShell，右键以管理员身份运行，依次执行：

PowerShell 命令

若 Status 是 Stopped，运行：

PowerShell 命令
Start-Service -Name MySQL84

关闭这个管理员窗口。接下来编辑项目配置和启动前后端，继续使用第 4 步的普通 PowerShell，保持同一个 Windows 用户。可以先检查数据库端口：

PowerShell 命令
Test-NetConnection -ComputerName 127.0.0.1 -Port 3306

看到 TcpTestSucceeded : True 表示端口能连接；这还不能证明数据库账号密码正确，继续执行下一步。

C4 登录数据库并创建项目专用库和账号

先在普通 PowerShell 执行下面命令，-p 后不要填写密码：

PowerShell 命令
& 'C:\Program Files\MySQL\MySQL Server 8.4\bin\mysql.exe' --host=127.0.0.1 --port=3306 --user=root -p

看到 Enter password: 后输入 C2 设置的 MySQL root 密码并回车。输入时不显示字符是正常的。成功后提示符从 PS ...> 变成 mysql>。

下面是 SQL，只粘贴到 mysql> 中，不要直接粘贴到 PowerShell。 先自己准备一份项目数据库密码，建议使用密码管理器生成至少 16 位的字母、数字和英文符号组合；为便于直接填入这个 SQL 示例，避开单引号、反斜杠和空白。将两处 REPLACE_WITH_YOUR_DATABASE_PASSWORD 都替换成同一个实际密码，再逐条执行：

SQL 命令 · 只在 mysql> 中执行
CREATE DATABASE IF NOT EXISTS face_attendance CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE USER IF NOT EXISTS 'face_attendance'@'127.0.0.1' IDENTIFIED BY 'REPLACE_WITH_YOUR_DATABASE_PASSWORD';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, INDEX, REFERENCES, DROP ON face_attendance.* TO 'face_attendance'@'127.0.0.1';
CREATE USER IF NOT EXISTS 'face_attendance'@'localhost' IDENTIFIED BY 'REPLACE_WITH_YOUR_DATABASE_PASSWORD';
GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, INDEX, REFERENCES, DROP ON face_attendance.* TO 'face_attendance'@'localhost';

两种来源主机写法都限制在本机，用于兼容本地名称解析；没有给项目账号整个 MySQL 服务器的管理权限。出现 Query OK 表示语句成功。若账号已存在，IF NOT EXISTS 不会重置其密码，应使用那个账号原本的密码，或请维护者确认处理，不要继续猜测。

检查数据库已创建：

SQL 命令 · 只在 mysql> 中执行
SHOW DATABASES LIKE 'face_attendance';

看到 face_attendance 后，退出数据库命令行，回到 PowerShell：

SQL 命令 · 只在 mysql> 中执行
exit;

然后用项目专用账号检查实际登录：

PowerShell 命令
& 'C:\Program Files\MySQL\MySQL Server 8.4\bin\mysql.exe' --host=127.0.0.1 --port=3306 --user=face_attendance -p face_attendance

这次输入刚刚创建的项目数据库密码。进入 mysql> 后执行：

SQL 命令 · 只在 mysql> 中执行
SELECT DATABASE(), CURRENT_USER(), VERSION();

结果应包含数据库 face_attendance、项目账号和 8.4... 版本。再输入 exit; 返回 PowerShell。MySQL 连接参数说明

C5 把数据库连接写进项目配置

在项目根目录的普通 PowerShell 打开 .env：

PowerShell 命令
notepad.exe .env

找到对应项目并修改，不要重复追加同名项。示例中的密码占位文字必须换成 C4 已验证能登录的实际密码：

配置示例或预期结果
DB_URL=jdbc:mysql://127.0.0.1:3306/face_attendance?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
DB_USERNAME=face_attendance
DB_PASSWORD=REPLACE_WITH_YOUR_DATABASE_PASSWORD

保存并关闭记事本。DB_URL 必须保持为完整的一行；如果安装时使用的不是 3306，地址中的端口与 DB_PORT 要一起更改。

不要修改 FACE_ENCRYPTION_KEY 和 INTERNAL_API_KEY，也不要新增 SPRING_DATASOURCE_* 项。启动脚本会在加 -MySql 时处理数据库覆盖。

账号用在哪里密码来源

C6 启动连接 MySQL 的后端和前端

确认 MySQL 服务仍处于 Running。若是新打开的普通 PowerShell 窗口，先执行第 4 步的当前窗口脚本策略设置。如果此前启动过 H2 模式，先在项目根目录停止本项目前后端，两个模式不能同时占用 8080 和 5173：

PowerShell 命令
.\scripts\stop.ps1

确认停止脚本成功后，运行带 -MySql 的命令：

PowerShell 命令
.\scripts\start.ps1 -Dev -BusinessOnly -MySql -TargetEnvironment

应该先看到 Development database: MySQL，随后出现后端、前端启动提示。后端首次连接空库时，Flyway 会自动建表和记录迁移版本，因此不需要手工导入业务表结构，也不用在 Workbench 逐张建表。

启动失败时先看 .runtime\backend.stdout.log 和 .runtime\backend.stderr.log；不要转而使用不带 -MySql 的命令掩盖数据库连接错误。

C7 确认程序确实连接了 MySQL

先打开网站，并执行健康检查：

PowerShell 命令
Start-Process 'http://localhost:5173'
PowerShell 命令
(Invoke-WebRequest -Uri 'http://localhost:5173/api/v1/health' -UseBasicParsing -TimeoutSec 15).StatusCode

健康检查返回 200 后，用 C4 的项目账号命令再次进入 MySQL，执行：

SQL 命令 · 只在 mysql> 中执行
SHOW TABLES;
SELECT version, success FROM flyway_schema_history;
SELECT COUNT(*) AS account_count FROM sys_user;

应看到 employee、sys_user、attendance_daily 等业务表，迁移记录 success 为 1，账号数量至少为 1。

接着按第 8 步登录网页。首次使用新的 MySQL 空库时，会重新创建初始管理员，使用当前 .env 的初始密码登录并改密；原 H2 中改过的密码和员工记录不会自动出现在这里。再在网页创建一个虚构测试员工，执行下面的查询，应能在 MySQL 中查到它：

SQL 命令 · 只在 mysql> 中执行
SELECT employee_no, name FROM employee ORDER BY id DESC LIMIT 5;

这一步把“网页能打开”和“业务数据确实写入 MySQL”联系起来。

C8 下次启动和停止

启动顺序固定为：MySQL 服务 → Java 后端 → Vue 前端 → 浏览器。

  1. 在 Windows 服务中确认 MySQL84 正在运行，未运行时先启动。
  2. 在项目根目录打开普通 PowerShell，设置当前窗口脚本执行策略。
  3. 执行 scripts\stop.ps1 清理上次本项目进程记录，成功后运行 scripts\start.ps1 -Dev -BusinessOnly -MySql -TargetEnvironment。
  4. 打开 http://localhost:5173，使用这个 MySQL 数据库中当前有效的网页账号密码。

使用完毕，执行 scripts\stop.ps1 只会停止本项目服务，不会停止 MySQL，因为其他应用也可能使用它。只想关闭网页和本项目前后端时，可以让 MySQL 继续运行。确认其他程序都不需要该数据库服务后，才在“服务”窗口右键 MySQL84 选择“停止”，或在管理员 PowerShell 执行：

PowerShell 命令
Stop-Service -Name MySQL84

MySQL 数据由它自己的数据目录保存，不在 backend\data\attendance.mv.db。不要复制或删除 H2 文件来操作 MySQL 数据；需要备份时看 部署与备份说明。

# vivo 手机作为打卡设备

配置日期：2026-10-28。项目目录：`F:\人脸识别\face-attendance2\face-attendance`。

## 当前电脑端配置

- 当前电脑 WLAN IPv4：`192.168.10.46`，局域网网段 `192.168.10.0/24`。
- 手机访问地址：`https://192.168.10.46:5173`。
- 电脑同时使用的管理地址：`http://localhost:5174`，仅绑定本机回环，不需要电脑安装 CA。两个入口连接同一后端和数据库，各自登录和授权。电脑 HTTP 代理仅对回环入口移除响应 Cookie 的 Secure 属性，手机 HTTPS 入口仍保留 Secure。
- 使用 Vite 的局域网 HTTPS 开发入口，沿用 H2、Java 后端和 Python 人脸服务，无需安装 Nginx 或 MySQL。
- 已增加 `启动手机打卡.cmd` 和 `scripts/start-phone.ps1`。
- 在电脑上已验证证书链/IP、网页、API 均正常，CSRF 接口返回的会话 Cookie 具有 Secure 属性。
- 尚需用户以管理员身份放行防火墙，以及在真实手机安装证书、授权浏览器和测试摄像头。
- 此入口用于同一可信局域网的小组演示。不能据此宣称已完成正式公网部署。

## 1. 放行电脑防火墙（一次性）

当前自动化会话添加规则时被 Windows 拒绝，防火墙规则尚未创建。

在 Windows 开始菜单搜索“Windows PowerShell”，右键选择“以管理员身份运行”，执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "F:\人脸识别\face-attendance2\face-attendance\scripts\allow-phone-firewall.ps1"
```

看到规则已启用、Action 为 Allow 即可。该规则只允许项目自带 Node 程序，在电脑地址 `192.168.10.46` 的 TCP 5173 端口，接受 `192.168.10.0/24` 的连接。不开放 8080、8000 或数据库端口。

脚本提示规则已存在时，不要反复创建；在 Windows 高级防火墙中查看名为 `FaceAttendance2-LAN-HTTPS-5173` 的规则及其作用范围。

## 2. 手机与电脑连接同一个 Wi-Fi

vivo 打开“设置 → WLAN”，连接电脑正在使用的同一个 Wi-Fi，暂时不要使用流量网络访问这个地址。

校园网、访客 Wi-Fi 可能隔离不同客户端。即使 Wi-Fi 名称相同也可能无法互访；先完成防火墙再判断。如果网络隔离，需要换成允许设备互访的路由器网络。换网络后电脑 IP 通常变化，需同步重新签发对应 IP 的服务端证书、修改启动 IP 和防火墙规则，旧地址不会自动跟随。

## 4. 在 vivo 安装 CA 证书

OriginOS/Funtouch OS 各版本菜单不同，优先用设置顶部的搜索框搜索“安装证书”“CA证书”或“凭据”。常见入口在“安全/安全与隐私 → 更多安全设置 → 从手机存储安装/加密与凭据”。vivo 官方旧版手册也将“从手机存储和 SD 卡安装”列在安全设置中，但不能保证所有新型号的菜单完全相同。

进入证书安装页面后：

1. 选择 **CA 证书**，不要选择 WLAN 证书、VPN 和应用用户证书。
2. 按系统要求输入锁屏密码。
3. 从 Download 文件夹选择 `手机安装-打卡测试CA.cer`。
4. 核对证书名称并完成安装。在“受信任的凭据 → 用户”中确认该证书存在。

手机可能提示网络可能受到监控，这是安装用户 CA 后的系统提醒。仅在本人测试设备上安装本次已核对的证书；测试结束后可在用户凭据中移除它。电脑端未自动安装这张 CA，所以电脑浏览器仍可能提示不信任；本次电脑 HTTPS 检查是显式指定本次 CA 完成的。

参考：[vivo 安全设置手册](https://www.vivo.com.cn/instructions/index?modelName=PD1708&pageId=26661)、[Android 证书管理说明](https://support.google.com/pixelphone/answer/2844832?hl=zh-Hans)。后者用于解释 Android 通用机制，不代表 vivo 菜单路径。

## 5. 手机打开网页并授权

先使用手机系统浏览器，在地址栏完整输入：

```text
https://192.168.10.46:5173
```

不能写成 http，不能使用 localhost，不要在 QQ/微信内置网页里操作。安装证书后如果仍出现证书不受信任或名称不匹配，先处理证书问题，不以跳过警告作为摄像头验收通过。

1. 在这个手机浏览器登录管理员账号。
2. 如是首次登录，先完成改密。
3. 打开“打卡设备”，点击“授权本浏览器”。
4. 名称填写“我的 vivo 手机”，确认授权。
5. 退出管理员账号，打开 `https://192.168.10.46:5173/kiosk`。
6. 刷新设备状态，允许浏览器摄像头权限，选择有效时段内的签到或签退。

如果摄像头权限已被拒绝，到“设置 → 应用/应用管理 → 当前浏览器 → 权限 → 相机”中允许，并检查浏览器对该站点的相机权限。菜单随系统版本变化，以实际页面为准。

授权绑定当前手机浏览器的 Cookie，有效期默认 7 天。电脑浏览器的授权不会自动转移给手机，换浏览器、使用无痕模式或清 Cookie 后需重新授权。

## 6. 以后如何启动和停止

服务当前已按手机 HTTPS 模式启动，无需重复启动。以后使用：

1. 保持电脑 IP 为 `192.168.10.46`。
2. 重启前先双击 `停止项目.cmd`，确认停止成功。
3. 双击 `启动手机打卡.cmd`。
4. 手机通过上述 HTTPS 地址访问，电脑保持开机。

普通 `启动完整刷脸.cmd` 会回到本机 HTTP 模式，不提供此次手机 HTTPS 入口。同一端口不能同时启动两种模式。

## 7. 按现象排查

| 现象 | 检查顺序 |
|---|---|
| 手机连接超时 | 电脑服务是否运行 → 管理员防火墙脚本是否成功 → 是否同一 Wi-Fi → 网络是否隔离客户端 |
| 证书警告 | 安装的是本次 CA 吗 → 手机是否信任它 → 输入 IP 是否仍为 192.168.10.46 → 手机日期是否正确 |
| 页面正常，相机打不开 | 必须 HTTPS 且无证书错误 → 手机和浏览器站点相机权限 → 相机是否被其他应用占用 |
| 登录后仍显示未授权 | 在手机当前浏览器中执行“授权本浏览器”，不要仅在电脑上授权 |
| 公共打卡显示未校准/模型未就绪 | 与手机联网无关，回管理员“系统运行”检查当前模型、人员库、参数状态 |
| 动作验证超时 | 与签退窗口及证书无直接关系；仍需排查原有动作检测与帧处理性能问题，换手机不保证解决 |

手机负责采集，识别推理仍在电脑上执行。手机真机兼容性、实际 Wi-Fi 连通性及动作成功率需要用户在真实设备上完成验证。

# 全天测试打卡与动作验证流程改进

## 新增功能

管理员可在“系统运行”开启全天测试打卡，立即允许在非正式窗口内签到和签退。测试模式不绕过设备授权、人脸身份、模型版本、人员库同步、校准确认或已启用的动作检测。

成功记录以 FACE_TEST 单独保存，可在“考勤记录”下方查看。测试数据不进入正式日考勤、仪表盘和导出报表，不阻止请假审批，也不与正式打卡互相触发去重。员工仅能查看自己的测试记录。

## 动作验证流程

- 浏览器等待算法连接就绪再发送首帧，每次等待上一帧处理确认后才发送下一帧。
- Java 透传处理确认；欢迎消息不作为帧确认，也不解除正在处理的帧。
- 浏览器、Java 和 Python 的采集时限统一为35秒；浏览器另留2秒接收结果，会话总期限仍为60秒。
- 保留80帧、单帧200KiB和累计12MiB限制。快速处理时仍可能先达到帧数上限。
- 动作提示分为自然状态、闭眼或张嘴、恢复自然状态，减少在基准阶段提前操作的误解。

## 兼容与升级

V2 数据库迁移仅新增设置和会话的 test_mode 字段，默认关闭。使用既有事件 source 字段区分测试与正式数据。升级前备份数据库，不能删除已执行的迁移或修改 V1。旧后端不能直接替换已经升级数据库的新后端；回退应使用匹配版本的数据库备份。

## 验证

- 后端31项回归测试通过，覆盖时间窗口、测试记录隔离、正式去重独立、员工权限及转发确认。
- 算法48项测试通过。
- 前端6项摄像头协议测试、TypeScript检查通过。
- 本机新后端构建、数据库迁移、健康接口和模型加载已验证。

## 已知限制

本版没有降低人脸识别阈值。单帧匹配分数或分差下降、候选变化及首帧一致性不足仍会拒绝打卡。“身份不稳定”尚需结合真实样本和受控诊断排查，不宣称本版已解决。真人动作成功率、不同设备性能及识别准确率需要实际验证。

# 员工端与定位考勤

## 入口与功能

员工与管理员使用同一个登录页。员工登录后进入 `/employee`，管理员进入管理工作台。

员工端提供：

- 今日签到、签退、当前班次与可打卡时段。
- 定位签到和签退，查看启用地点、范围与定位结果。
- 个人考勤筛选、报表导出，以及从异常记录发起补卡。
- 请假与补卡申请、撤销待审批申请、查看审批结果和意见。
- 本月考勤汇总、待审批申请数量、今日打卡记录。
- 个人档案、人脸录入状态、修改密码和退出登录。

员工账号仍由管理员在「人员与部门」中创建并关联员工档案。首次登录必须修改初始密码；个人页面和接口按当前登录账号读取本人数据。

## 管理员配置

打开「组织管理 → 考勤方式与地点」。支持以下方式：

| 方式 | 员工打卡入口 |
| --- | --- |
| 人脸打卡 | 已授权浏览器的公共刷脸终端 |
| 定位打卡 | 员工登录后的工作台 |
| 人脸或定位 | 上述两种方式任选，归入同一份考勤记录 |

升级后默认保留「人脸打卡」。启用定位的步骤：

1. 在「考勤地点」添加地点名称和地址说明。
2. 在实际办公地点点击「使用当前位置」，或填写准确的 WGS84 经纬度。
3. 设置考勤半径（50–5000 米）、允许定位误差（默认100米，可设1–500米）并启用地点。实际误差上限不超过半径的一半。
4. 保存地点后，选择「定位打卡」或「人脸或定位」，保存考勤方式。

可以配置多个地点，员工位于任意启用地点内即可打卡。地点和考勤方式保存后立即生效。定位开启时，至少保留一个启用地点；如需删除最后一个地点，先切换到人脸方式。

坐标使用浏览器定位的 WGS84 坐标系。其他地图服务的坐标需先确认坐标系，不能直接混用 GCJ-02 或 BD-09 坐标。

签到、签退时间和迟到早退规则继续在「规则与日历」配置。考勤地点负责判断位置，班次规则负责判断时间。

## 员工定位打卡

1. 登录自己的员工账号，打开工作台。
2. 点击「定位签到」或「定位签退」，允许浏览器使用定位。
3. 系统获取本次位置，并检查考勤地点、范围与打卡时间。
4. 查看成功结果、服务端记录时间及更新后的今日考勤。

定位仅在点击操作时获取，不在后台持续追踪。服务端校验：

- 当前账号关联在职员工，且已修改初始密码。
- 今天为工作日、没有已批准的整天请假，且在相应签到或签退窗口内。
- 位置信息在 60 秒内，设备时间没有明显超前。
- 位置在启用地点半径内；估计误差不超过该地点配置的上限，也不超过该地点半径的一半。旧地点默认仍为100米。
- 30 秒内不重复接受同一员工的同类型正式打卡。

提交使用独立请求编号。同一请求因网络问题重试时取回原记录，不重复写入。成功记录使用服务器时间，签到取首条、签退取末条；定位和正式人脸记录共同参与日报、月度汇总与导出。

原始员工经纬度不写入打卡记录，记录保留地点、当时地点名称、距离、精度和请求摘要。地点删除后，既有记录仍保留。

定位依赖浏览器和设备提供的位置；该能力用于范围考勤，并不等同于硬件级位置认证。

## 请假与补卡

工作台可直接发起请假或补卡。个人考勤页中的缺卡、迟到和早退记录提供补卡入口，自动带入日期和签到/签退类型。

请假按整天申请。补卡沿用既有规则：最近 7 个已结束自然日中的在职工作日，所选时间必须落在对应打卡窗口内，已批准请假日期不能补卡。审批通过后重算考勤，并保留原始打卡记录。

管理员在「请假与补卡」的审批页面处理申请，员工可查看结果、审批意见，并撤销本人尚未处理的申请。

## 手机访问

浏览器定位需要安全上下文和用户授权。手机使用已信任的 HTTPS 地址访问登录页，登录后进入员工端；本机开发可使用 localhost。具体部署沿用 [手机部署说明](repository-phone-setup.md)。浏览器要求见 [MDN：getCurrentPosition](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/getCurrentPosition)。

公共人脸打卡继续使用设备授权；员工定位打卡使用本人登录会话，无需给每个员工浏览器发放公共终端授权。

## 升级与接口

重新构建并重启后端和前端后生效。后端启动时自动执行 `V3__attendance_locations.sql`，新增考勤方式、地点表及定位记录字段；后续 `V4__location_accuracy_limit.sql` 为地点增加默认100米的误差上限，保留已有数据。升级前应停机备份数据库与对应JAR。

| 接口 | 用途 | 权限 |
| --- | --- | --- |
| `GET /api/v1/employee/home` | 员工工作台数据 | 本人登录账号 |
| `GET /api/v1/employee/profile` | 员工资料 | 本人登录账号 |
| `POST /api/v1/employee/location-punch` | 定位签到、签退 | 本人登录账号 |
| `GET /api/v1/attendance-policy` | 当前考勤方式 | 登录账号 |
| `PUT /api/v1/attendance-policy` | 设置考勤方式 | 管理员 |
| `GET /api/v1/attendance-locations` | 考勤地点；员工仅返回启用地点 | 登录账号 |
| `POST /api/v1/attendance-locations` | 新建地点 | 管理员 |
| `PUT /api/v1/attendance-locations/{id}` | 修改地点 | 管理员 |
| `DELETE /api/v1/attendance-locations/{id}` | 删除地点 | 管理员 |

定位请求示例结构：

```json
{
  "type": "IN",
  "latitude": 31.230416,
  "longitude": 121.473701,
  "accuracyMeters": 12,
  "capturedAt": 1793581500000,
  "requestId": "71ccab4f-0be1-4d85-a749-d7667f025b38"
}
```

`capturedAt` 使用本次浏览器定位返回的毫秒时间戳；每次新的打卡操作生成 UUID，重试同一操作保留原请求内容。示例坐标、时间和编号仅说明字段，不是可直接重放的打卡凭据。

原有 `/attendance`、`/leave-requests`、`/correction-requests` 和人脸识别接口保持兼容。全天测试开关只影响原有测试人脸记录，定位打卡始终按正式考勤规则执行。

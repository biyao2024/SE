# 真人刷脸操作步骤

适用于本次 Windows x64、Python 3.11、CPU 模型环境。当前先完成技术验证；根据你的安排，真人摄像头操作和独立样本校准留到方便时进行。公开样本的接口测试不能代替下面的验收。

## 1. 启动服务并登录

本机项目目录为 `D:\SE\face-attendance`。双击 `启动完整刷脸.cmd`，或在项目根目录打开 PowerShell：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\scripts\start.ps1 -Dev -TargetEnvironment
```

如果服务已经运行，直接访问网页，不要重复启动。浏览器打开 [管理页面](http://localhost:5173)。H2 数据库随 Java 后端一起启动，无需安装或另外启动数据库。`启动项目.cmd` 只启动业务预览，刷脸要使用“启动完整刷脸”。

首次账号和密码在本机 `.env` 的 `BOOTSTRAP_ADMIN_USERNAME`、`BOOTSTRAP_ADMIN_PASSWORD` 中查看。若已经修改过密码，使用修改后的密码；旧初始密码不会重置现有账号。不要重新生成 `.env` 来解决登录错误。

进入“系统运行”，点击“刷新状态”。业务数据库和算法服务应正常，识别模型应显示真实版本，人员库应“已同步”。如果尚未同步，点击“重新同步人员库”。服务刚启动时模型需要加载，稍后再刷新。

## 2. 建档并录入三张人脸

1. 进入“人员与部门”，先用“部门管理”创建部门，再点“新建员工”。填写工号、姓名、部门和不晚于今天的入职日期，保存档案。管理员登录账号本身不等于员工档案。
2. 在对应员工行点击“录入人脸”。核对本人身份并说明用途、保存期限、删除及替代方式，取得同意后勾选确认框。
3. 点击“打开摄像头”，允许浏览器使用摄像头。关闭其他占用相机的软件；正面光照、画面只保留一人。
4. 按页面顺序分别采集“正脸”“轻微左转”“轻微右转”，不要大幅转头。三张采集结束后点击“提交并验证”。
5. 确认出现“人脸模板录入成功”、员工状态变为“已录入”。返回“系统运行”重新同步人员库。

在线录入仅保存加密特征，原图不会写入业务数据库。若提示模糊、脸太小、角度过大、图像不一致或重复绑定，根据提示重新采集；不要通过降低阈值强行提交。模型版本发生变化时，先确认要迁移的范围，再删除全部在职员工的旧版本模板，之后重新录入、同步并校准；旧版本模板尚存时会阻止新的录入。历史考勤不会因删除模板被删除。

## 3. 用真实样本校准

公共打卡在“未校准”状态下保持关闭。不要将默认相似度 0.50、分差 0.08 勾选为“已完成校准”。

已提供三个离线工具：`capture_samples` 采集独立图片、`score_samples` 用真实模型产生分数、`calibrate` 选择参数并评估测试集。完整命令与清单格式见 [算法说明：采集与校准](../algorithm/Readme.md)。

每位已录入参与者准备 3 张录入图像，以及另外两次采集的校准、测试图像各 10～20 张；另留至少一位同意参与的未录入者，在校准和测试组各采集 10～20 张。三组不能复用同一图像或同一批连续拍摄。多位参与者时，所有已录入人员都要包含在两组中。

离线采集会暂存原图，区别于网页录入；请先约定删除期限。`employee-id` 使用员工档案内部数字 ID，不是工号。可在已登录浏览器打开 [员工档案接口](http://localhost:5173/api/v1/employees?page=0&size=100)，按姓名/工号核对对应 `id`；只在本机查看，不对外分享完整响应。

清单准备好后，在 `algorithm` 文件夹执行：

```powershell
.\.venv-runtime\Scripts\python.exe -m scripts.score_samples --manifest experiments\pilot\dataset.json --output-dir experiments\run-001 --model-dir models
.\.venv-runtime\Scripts\python.exe -m scripts.calibrate --samples experiments\run-001\scores.csv --run-report experiments\run-001\run.json --output experiments\run-001\calibration-result.json --max-unknown-acceptance 0.01 --max-wrong-identity 0.01
```

每次使用新的输出目录，保留 `scores.csv`、`run.json` 和结果报告。0.01 是筛选目标，不是准确率承诺。报告没有可用参数时，查清质量、标签和样本问题后重新采集，不能用手填分数替代。

报告只评价离线 enrollment 图片构成的固定人员库，以及单帧识别；动作与连续帧还需实测。**它不会读取网页中保存的模板，也不会证明网页人员库已校准。即使人员 ID 相同，重新采集的三张图片仍是另一份模板。** 当前尚无离线人员库自动导入或业务人员库自动评分桥接，报告参数只能作为网页候选参数。

正式放行前，还需在受控实验中针对实际业务模板库，用独立的已知和未知人员样本验证候选参数，并记录模型版本、人员库版本、人数、接受与拒绝结果。完成后才可在“系统运行”填写相似度阈值和分差、勾选已完成校准并保存。当前技术验收不包含这一步；只有离线报告时先保持未确认。修改模板、增加候选人数或调整阈值后重新验证。

## 4. 授权设备并本人打卡

1. 管理员进入“打卡设备”，授权当前浏览器。授权与浏览器 Cookie 绑定，换浏览器、无痕窗口或清 Cookie 后需重新授权。
2. 保持“系统运行”的随机动作检测开启。打开 [公共打卡页面](http://localhost:5173/kiosk)，点击刷新检查；显示未校准或模型未就绪时先处理对应状态。
3. 在有效时段选择上班签到或下班签退。默认签到为 06:00～11:59:59，签退为 12:00～23:59:59；规则修改次日生效，实际以“规则与日历”为准。
4. 打开摄像头，让本人单独正对镜头。先自然睁眼、闭嘴，随后按随机提示眨眼、张嘴，并回到自然状态；全过程不要换人或移开镜头。
5. 成功后到“考勤记录”核对人员、日期和类型。重复操作应出现重复打卡提示，不应新增重复记录。

随后分别验证陌生人、静态照片、多人入镜、撤销设备授权和非打卡时段均不能产生成功考勤。动作检测是研究方案，静态照片测试通过不能证明能抵抗预录视频或换脸攻击。

## 5. 关闭与排错

退出网页不会停止服务。结束后双击 `停止项目.cmd`，或在项目根目录执行 `scripts\stop.ps1`。它只停止本项目记录且身份匹配的进程。

| 现象 | 操作 |
| --- | --- |
| 端口已占用 | 先看项目是否已经运行；需重启时先正常停止，不强行结束未知进程 |
| 算法服务不可用 | 看 `.runtime/algorithm.stderr.log`，检查模型、依赖及真实加载结果 |
| 人员库同步失败 | 点击重新同步，检查模型版本；版本迁移需先删除全部在职员工旧模板，再录入和校准 |
| 相机打不开 | 在浏览器网站权限中允许摄像头；关闭其他占用相机的软件 |
| 请管理员完成校准 | 按第 3 节采集和校准；这不是安装失败 |
| 非打卡时段 | 核对当前时间、签到/签退选择及当天生效规则 |
| 登录失败 | 使用改密后的密码，保留请求编号排查；不要覆盖 `.env` 或删除数据库 |

真人验收完成后，请记录日期、模型版本、设备/浏览器、已知与未知人数、成功/拒绝/重复结果和校准报告位置，再将这一部分标为通过。

# 计划调整与实施边界

依据 `D:\SE\plan.md`，保留Java业务裁决、Python内部推理、单机局域网、授权浏览器、三模板录入、固定日班、单级审批和公开设备信息脱敏的主线。不修改原计划文件。

| 调整 | 原因及影响 |
| --- | --- |
| 增加H2文件数据库开发配置 | 当前环境未提供运行中的MySQL，可先验证业务。生产默认仍为MySQL8.4，H2测试不能替代MySQL实测。 |
| 使用pnpm锁定前端依赖 | 工作环境已有Node/pnpm；同一锁文件用于安装与构建。无需同时维护npm和pnpm锁文件。 |
| 未确认阈值校准时阻断刷脸 | 原计划要求独立校准；预置数值只是待校准起点，不能当作已验证结论。 |
| 模型由操作者下载并生成哈希清单 | 模型体积、许可和真实性需要单独管理；源码不内置模型，不自动接受未知权重。 |
| 更换模型必须重新录入并校准 | 任何有效模板的模型版本不同于当前模型时阻断同步；先删除不兼容的旧模板，再现场重新采集，避免不同特征空间混用。 |
| 软件实现与真机实验分开记录 | 本次交付不能在没有摄像头、手机、知情参与者的情况下完成8周计划中的真实实验；未执行的步骤保留验收清单。 |
| 不默认建立真实人员或导入生物特征 | 通过界面创建虚构演示员工，真实采集须先完成现场身份核对和告知同意。 |
| 对单机历史查询与建档回溯设置上限 | 单次查询最多366天，建档入职日最多回溯365天，避免首次补算无界增长；更早历史数据需要后续迁移方案。 |
| 工号和入职日期建档后固定，离职后不直接重新启用 | 第一版用单一在职区间保存资格；再次入职使用新工号档案，避免改写历史。后续可增加employment_period表支持同人多次入职。 |
| 初始管理员独立于员工档案 | 初始管理员只负责管理，不能提交员工申请；需要申请功能的管理员通过新建员工并选择ADMIN创建，自己的申请交另一管理员处理。 |
| 验收后保留期限采用人工治理 | “验收后30天”需要实际验收日期与人员政策；没有这两项时不安排自动删除。已有面部模板删除和停用路径可用于主动处理。 |

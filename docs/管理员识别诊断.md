# 管理员识别诊断

## 使用

1. 管理员登录，在“系统运行”开启“全天测试打卡”，保存设置。
2. 在“打卡设备”授权当前浏览器，确认模型就绪、人员库同步及已有的校准确认状态。
3. 从侧栏“识别诊断”或“系统运行 → 打开管理员识别诊断”进入 `/diagnostics`。
4. 选择测试签到或签退，正对镜头并按分阶段提示操作。
5. 向下查看最新一帧数值卡片及最近80帧表格。失败帧在本页保留，重新开始、离开页面会清空。成功的测试打卡仍保存到测试记录中，不进入正式考勤。

## 数值含义

| 项目 | 含义 |
|---|---|
| 身份分数 | 当前画面与实际业务人员库第一候选的最高模板余弦相似度，不是概率 |
| 候选分差 | 第一与第二候选相似度之差；只有一个有效人员时不使用，显示“—” |
| 首帧相似度 | 当前人脸特征与本会话首个被接受画面的相似度；参照尚未建立时显示“—” |
| 左/右闭眼系数、张嘴系数 | MediaPipe 输出的动作系数，不是身份匹配分数；关闭动作检测时不测量，显示“—” |
| 当前动作及阶段 | 该帧处理前的动作状态。-1为基准或收尾，0为自然状态，1为闭眼/张嘴，2为恢复 |
| 处理毫秒 | 算法解码、等待推理锁、模型推理及匹配等处理时间；不包含浏览器网络往返 |

身份门槛与分差门槛是当前会话使用的配置快照。身份检查“通过”不代表动作验证或整次打卡已完成。画面质量未通过、没有人脸或模型失败时，未计算的身份指标保持空白，不能把空白当作零分。

## 根据提示定位问题

- 身份相似度不足：当前帧与业务模板的匹配未达到门槛。
- 候选分差不足：有多名有效人员，第一与第二名过于接近。
- 候选人员改变：同一会话匹配到了另一位人员。
- 与首帧相似度不足：当前画面与会话参照不一致。
- 画面质量未通过：结合 NO_FACE、LOW_QUALITY 等代码检查采集条件。

先保存文字说明或必要的诊断截图，再针对模板、光线、画面稳定性或动作阶段定位问题。本版只增加观察能力，不修改识别分数公式、身份阈值、动作系数门槛或失败判定。

## 权限和数据范围

`POST /api/v1/kiosk/diagnostics/sessions` 和 `/api/v1/kiosk/diagnostics/stream` 是独立管理员入口，需要有效管理员登录、已开启测试模式和当前浏览器设备凭据。每帧及转发诊断前重新检查登录与账户有效性。

算法只在经内部密钥保护的协议中携带数值，Java 对管理员数据使用字段白名单；公共 WebSocket 不转发诊断字段，也不能通过 query 参数开启。诊断不包含姓名、候选员工编号、原图或512维特征，不写数据库、文件日志或浏览器持久存储。页面仅在内存保留最近80帧，截图可能包含实验信息，应自行控制分享范围。

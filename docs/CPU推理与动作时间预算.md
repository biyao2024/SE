# CPU 推理与动作时间预算（本机试用已确认）

本轮截图包含两类失败，不应都归为超时：张嘴系数0.800时身份分数0.673，低于配置0.700，会被身份门槛拒绝；另一次停留在眨眼恢复阶段，尚未完成两个动作。

## 修改

InsightFace 0.7.3 的公开 get_model 入口没有将 sess_options 传给模型路由器。新增应用内 CPU 适配器，使用固定版本 ModelRouter 显式创建检测、3D姿态、识别三个必需模型，设置每模型8个 intra-op线程、1个 inter-op线程及顺序执行。没有修改第三方安装文件、模型权重、检测尺寸、特征提取公式或 CPU provider；仍加载3D姿态模块并执行质量检查。

可通过 `CPU_INFERENCE_THREADS` 设置1～8，默认8。本机对已有公开肖像样本测量，在线程池调用路径下默认配置3次中位数284.48ms，8线程239.47ms，与原特征余弦相似度1.00000000（输出精度范围）。这是单图小样本基准，不代表摄像头、并发、不同硬件或所有姿态的性能；不能据此声称用户的1.4秒延迟全部解决。

浏览器、Java、Python 的采集预算统一为50秒；浏览器留2秒收尾，整个会话仍最多60秒，80帧、200KiB单帧和12MiB累计限制保持。较快处理时可能先触发帧数上限。

张嘴提示改为适度张嘴并保持到闭嘴提示，不要求用力张到最大。自然睁眼0.30、闭眼0.55、闭嘴0.15、张嘴0.35及管理员配置的身份阈值不修改。

## 验收

在管理员诊断中观察单帧耗时和两个动作是否完成。张嘴时若身份分数下降，保留失败帧；不要仅为完成演示继续降低身份门槛。眼睛闭合约2秒再自然睁开，张嘴只需达到门槛并稳定保持，随后闭嘴。

仍需真人、陌生人和静态照片测试。本机试用已确认后发布；不同环境仍需验证。

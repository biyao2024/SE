# 操作说明与答辩演示

## 管理员

1. 用 `.env` 中的管理员账号登录。创建部门，再创建员工并填写唯一工号、姓名、入职日期、部门和账号初始密码。
2. 员工首次登录按页面提示修改密码。初始密码通过线下渠道交付，不放入日志、邮件模板或演示投影。
3. 现场确认身份并展示用途、数据保存、删除和替代方式；确认同意后进入人脸录入页面。
4. 允许摄像头，依次采集正脸、轻微左转和轻微右转；不要使用文件上传。每次采集都由Python检查单人、质量与特征一致性，疑似重复绑定会阻断。
5. 在准备作为公共打卡机的浏览器中进入设备管理，授权当前浏览器并命名。退出管理员账号后进入公共打卡页。授权是浏览器Cookie，有效期默认7天；清除Cookie、换浏览器或撤销授权后需要重新授权。
6. 根据已记录的实验数据在系统设置配置阈值与候选分差，并确认校准。是否启用随机动作检测由管理员决定；更改设置会使进行中的会话失效。
7. 管理固定日班、未来工作日例外、请假和补卡审批；变更规则从次日生效。审批前核实申请理由，自己的申请需另一位管理员处理。
8. 查询考勤、选择范围导出Excel，并在审计日志中核对关键操作。人员离职或停用后不能继续刷脸，但历史统计保留。

## 员工

登录后查看个人考勤、提交整天请假和最近7个已结束工作日的补卡。补卡要填写日期、签到/签退、时间和原因；申请时间必须位于该日相应打卡窗口。只能撤销仍待审批的申请，审批通过后记录以人工修正来源保留，不伪装为原始刷脸事件。

账号只能查看本人数据。申请日期重叠、请假与有效打卡冲突、重复待处理补卡都会被拒绝；请根据页面提示核对记录后处理。

## 公共打卡

选择上班签到或下班签退，允许摄像头，单人正对镜头。动作检测开启时按提示眨眼和张嘴，完成自然状态→动作→恢复的完整过程。服务端会验证连续身份和动作过程，前端按钮不能绕过检测。成功后仅显示脱敏身份和结果，约3秒清空；离开页面停止摄像头。

默认签到窗口06:00—11:59:59，签退窗口12:00—23:59:59。09:05:00及之前签到不算迟到，17:55:00及之后签退不算早退。首次有效签到和最后一次有效签退用于日报；30秒内同类重复请求不新增事件。当天尚未结束时不会提前判定缺勤。

遇到权限拒绝、模型不可用、网络断开或验证失败时重新开始；页面没有明确成功不能当作已完成打卡。需要人工处理时走补卡申请和审批，不通过伪造摄像头或直接修改数据库绕过流程。

## 8—12分钟答辩脚本

| 步骤 | 展示内容 | 必须满足 |
| --- | --- | --- |
| 1 | 架构与数据保护：Vue→Java→Python，模板AES-GCM | 不展示真实凭证或未脱敏人员数据 |
| 2 | 新建虚构演示员工，现场采集三姿态 | 已知情同意、模型与人员库就绪 |
| 3 | 授权浏览器并退出管理员，关闭动作检测刷脸 | 校准已完成；事件动作状态为跳过 |
| 4 | 开启动作检测，演示随机顺序与真人动作 | 旧会话失效后重新开始 |
| 5 | 测试打印/手机照片，并展示真实结果 | 不预设一定拒绝；记录失败原因和实验条件 |
| 6 | 展示迟到/早退/缺卡及规则快照 | 用已有脱敏记录或人工申请，不修改系统时钟造假 |
| 7 | 员工申请补卡、另一管理员审批 | 原事件保留，人工修正可追溯 |
| 8 | 查看月报并导出Excel，核对明细与统计 | 相同日期与人员范围 |
| 9 | 停止算法或撤销设备，验证不能成功打卡 | 恢复后重新创建会话 |

若当前仅具备业务开发环境，演示步骤2—5必须明确注明“等待真实模型/摄像头验收”，可以演示不可用提示，不能将占位UI或测试桩称为实际识别结果。
